## 14 停止UIの実装仕様（2026-09-27）

- `publicState.landStop` が空き地の配置待ち／自領地の強化先選択待ちを公開。手札の中身は公開せず、配置・強化・マーロー移動の可否だけを渡す。
- 配置できない空き地は「配置できるクリーチャーがない」。強化不可でマーロー移動のみ可能なときは「マーローを移動」。選択がない場合は既存ルール通り手番を進め、通知待ちを追加しない。
- カメラ移動中は情報窓と使用者を隠す。ズーム完了後に位置を確定し、静止表示。画面サイズ変更時は隠して再配置する。
- 発光は `PW.setInspectionGlow` で盤面内depth 97へ描画し、クリーチャー影・本体（100以上）と召喚士に重ねない。900msのフェード後は固定し、選択完了・他演出の開始・非表示時には破棄する。
- 強化先を選んだ後のレベル選択、城からの強化は既存UIを継続。停止したマスに強化対象を限定しない。
- 検証：`land_stop_test.js`、`land_stop_browser_test.js`、`enemy_land_browser_test.js`、`npm.cmd test`。ブラウザ確認はChrome 1440×900／1024×768／1280×720。記録は `output/land-stop-integration/` と `output/land-stop-preview/*integration*.log`。

## 別枠で確認するUI

- **ショップ**：商品棚、入店テロップ、購入状況。操作中の常設パネルを含むため、短時間メッセージと分けて検討。
- **ダイス・移動歩数**：結果の数字と専用演出。
- **領地強化・レベルダウン**：主にマスのFX。専用メッセージの新設は未決定。
- **進化**：承認済みの全画面演出。通常のメッセージ窓とは別。
- **通信・再接続、履歴ログ、操作ガイド**：システム案内／常設UI。イベント通知とは別。
- **リザルト**：順位・ハイライト・最終デッキの専用画面。今回の共通メッセージ刷新の対象外。

### 敵領地に停止（2026-09-27 実装）

- 採用プレビュー revision 7 を `public/board-enemy-land.js` / `.css` に移植。イラストは窓内、総HP＋DFを大きく表示。領地は色付き菱形マスで表し、一致時は属性色で周囲を発光。不一致は×と無発光。追加効果は左が攻め側、右が守り側。部分的な太線は禁止。
- `publicState.enemyLand` は現在の手番の敵領地選択待ちにだけ付与。実通行料・地形・能力と `landDefenseStats` の残HP／DF／合計／ATを表示する。DFの基礎計算を戦闘と共通化。攻撃クリーチャー・ウェポン未選択時の基準値であり、擬態・風刃・腐蝕など相手確定後の変化を先取りしない。

## 01〜03 経済メッセージの実装仕様（2026-09-25）

- `lastDice.castle` と門イベントに `beforeGold` / `afterGold` を記録。回復対象には `creatureId`・回復量・負傷の前後を記録し、Lv3進化や進化済みカードも現在のイラストで表示。古いセーブの表示は従来フィールドへフォールバックする。
- HUDの手持ちGは各演出の開始値で保持し、カウントアップ後に解放。別の演出用データでカードやGを変更しない。
- `GAME_TIMING.castleDuration` をサーバー・盤面・スマホで共有。基本6.5秒、回復対象12件は10.4秒、24件は19.2秒。3.5秒後に2ページ目、その後2.2秒ごとに切替。最後のページまで表示して自動消去する。刻印なしは4秒。
- サーバーの `availableAt` は城ズームと全ページの終了後。スマホとAPIはそれより前にカード選択を受け付けない。既存BOTの2倍速も同じ倍率を使用。再生中のアイコンの発光時間も倍率に合わせる。
- 門の通知は4.8秒。移動区間の待機時間へ加算し、門の表示中に次の選択が先行しないようにする。双門の取得済み刻印はイベント時点のスナップショットを使用。
- `economy_notice_test.js`: 実際の移動処理、両マップ、0・2・6・12・24領地、進化形、実残高、回復量、選択解禁、保存復元。

## 17 ゴール接近・目標達成（2026-09-27 実装）

- `broadcast` 前にサーバーの `points`（手持ちG・領地価値・称号を含む総資産）を集計。`goalProgress` と最大8件の `goalNotices` をセーブへ保存する。再到達・ターン変更で重複しない。8000Gへ直接到達した場合は7000G段階も消費済みにする。
- 7000G以上8000G未満で「8000G稼いで城へ向かえ」、8000G以上で「城へ戻れば勝利」。後者では城の周囲が発光。表示時の値とプレイヤー名・召喚士は到達イベントのスナップショット。表示キューは既存の戦闘・経済演出と直列化し、BOT倍速に対応。
- 待機中に総資産が基準未満へ下がった、破産した、試合終了した場合は古い通知を省略。7000G通知の待機中に8000Gへ達した場合も古い段階は省略する。
- ページ初回読込・別試合／復元実行単位への切替時には、取得済みの過去通知を再生しない。同じ接続の通知欠落後は保持されたイベント一覧から拾い、イベントIDで重複を防ぐ。
- 旧セーブには到達履歴がないため、復元時点で既に達成している段階を消費済みとして開始する。過去に到達した後で下落した履歴は旧セーブからは復元できない。
- 検証：`goal_notice_test.js`、`goal_notice_browser_test.js`、`npm.cmd test`。実スペル選択API→SSE→盤面通知、両閾値、直接到達、再到達、読み直し、保存復元、3画面サイズ、動き低減を確認。記録は `output/goal-notice-integration/`。
- 確認用プレビューも実装済み `BoardGoal.model` / CSS を使用。本番公開は別途。
