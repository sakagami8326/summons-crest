# BOTの進路・購入判断（v1.58改善）

以下はv1.58時点の先行改善記録。現在の統合仕様と検証方法は [v1.59 標準BOT](bot_v159.md) を参照。

## 範囲

`server.js` のBOT判断だけを変更する。両マップの配置、施設効果、周回報酬、通行料、カード効果、プレイヤーの購入制限、API、セーブ形式は変更しない。BOTに一定割合で外周を選ばせる処理は設けない。

## 進路

- 分岐の合法候補と到着予測は既存のサーバー処理を使用する。深淵の錨による実際の停止地点を評価し、旧マップの方向選択も途中の錨を認識する。
- 敵領地のリスク評価は `通行料×1.25＋max(0, 通行料＋100－現在の所持金)×1.5`。高額通行料を一定値で頭打ちにせず、相手への資金供給と手元資金不足を加味する。深淵標などを含む現行の通行料を参照する。
- 各進路の評価は `選べる到着候補の最高評価－未取得門（取得済みなら城）までの距離×2`。同点なら距離、さらに同点なら候補順。途中に別の分岐がある場合も自分で選べるため最高評価を使う。
- 勝利が確定する城到着を優先する。危険がなく着地価値が同程度なら短い経路が有利になる。
- 空き地に配置できる手札・資金がなければ空き地の評価を下げる。ショップは資金と補充の必要性で評価し、未公開の品ぞろえを先読みしない。
- 距離は小さな加点・減点であり、経済価値を厳密にG換算したものではない。外周の人間向けバランス改善とは別問題として扱う。

## 購入

- 最低150G、または手札で最も安いクリーチャーの召喚費＋100Gを残す。通常ダイスの1〜6歩以内に避けられない敵領地がある場合、その通行料＋100Gも確保する。分岐で避けられる領地は必須予算にしない。
- 購入後に上記の資金と、購入カードの召喚・使用費＋100Gを確保できなければ買わない。将来の周回収入などは予算に足さない。
- 手札・山札・捨て札を合算して不足を評価する。進化前後は同じ系統として数え、同系統をすでに2枚持っていれば追加購入しない。盤面に配置済みのカードは山札を圧迫しないためこの枚数に含めない。
- クリーチャーは3枚未満の緊急補充、5枚未満の補充、7枚未満の補充を段階的に評価し、既存戦力との差・召喚士の属性・領地連鎖・重複を加味する。
- ウェポンは攻撃・防御・打ち消しの不足を評価し、保有3枚以上では買い足さない。
- スペルは負傷した自領地、使用対象となる自領地・敵領地、召喚士との相性を評価する。同じ固定ダイス用途の重複やスペル過多を抑える。詳細は `botPurchaseScore` を正とする。
- 最終評価は必要性から `実売価格×0.6` と16枚超の山札膨張ペナルティを引いた値。最高候補でも20以下なら購入しない。購入後は毎回再計算し、1回の訪問では最大2枚まで。これはBOTの判断であり、人間の購入上限ではない。
- 不要カード除去サービスは今回のBOT対象外。値引きは表示価格をそのまま評価に使用する。

## 限界・検証

侵略で勝てると仮定して通行料を割り引かず、安全寄りに判断する。相手の非公開手札・山札は参照しない。侵略・防衛・スペル使用の既存判断は今回変更していないため、戦闘AI全体の最適化や勝率改善を保証するものではない。

`npm run test:bot-strategy` は高額領地・錨の回避、安全な近道、低資金、重複、必要な補充、不要なスペル、実際の購入後の予算再判定、非公開情報の非参照を検査する。両マップで各3乱数シードの4人戦を完走し、外周選択数も記録するが外周の強制選択率は設定しない。`npm test` でもこのテストを実行する。
