- 検証：`npm run test:phone-summoners-browser`。通常の `/phone` から実際に参加・選択・選び直し・他者選択の更新・再読み込み・試合開始まで確認。Android実機は別途確認。

## 戦闘補正

採用は C 案のミニカード。対象は **戦闘参加中のクリーチャー・使用ウェポン以外から受ける補正**。
参加クリーチャー自身の効果は固有能力欄、使用ウェポンの効果はウェポン欄に表示し、ミニカードを重複させない。

- 血染めの刃、炎の渦、リストア、追い風の導き、氷晶の勅令、紅蓮の方程式による炎の渦。
- 別のマスのクイーンベビー／クイーンが発生源になる女王の威光。最大値のみ適用し、自身の能力で同じ値を得ている場合は追加表示しない。
- 影響を受けるクリーチャーの斜め上に、既存アート＋能力値アイコン／DF＋数値。説明文を増やさない。
- 複数補正は並べる。緩やかな発光と光の走査。動きを減らす設定では静止した発光。
- サーバーが外部補正を公開用データとして作成し、戦闘結果に保存。戦闘終了後の消費済み状態やログ本文から推測しない。
- ウェポン選択中の数値は未公開ウェポンを除いて計算し、秘密の選択を漏らさない。

## スマホのカード選択

既存の手札カードを横一列に少し重ね、横スクロール。タップで拡大、全文を確認して確定。
全カードで表示規格を固定する。長文によってイラストや説明領域を移動しない。「詳細で全文表示」の重ねバッジは置かない。閉じるアイコンは中央揃え。

対象：戦線交代、手札上限、チェンジ、エヴォルヴ、鍛錬、魂の選別、フェイタルリワード、再鍛造、進化の胎動、墓守の協奏曲、忘却、選択ドロー、カード獲得。ショップ購入は従来の商品棚＋購入詳細 UI を維持する。

手札・領地・廃棄などはタブで区別し、領地のカードには土地番号を添える。ショップは購入できない商品も詳細閲覧できるが確定できない。

## 現在のデッキ一覧（07）

スマホ横画面に既存カードを固定規格で縮小し、8列で表示。同名カードも1枚ずつ並べ、枚数バッジは付けない。
上部は召喚士の顔、属性別枚数、クリーチャー・スペル・ウェポン・廃棄の順に配置。上部を固定し、一覧のみ縦スクロール。

## デッキ状況の取得・同期（2026-09-23）

- サーバーの `ownedCardSnapshot` が所持カードの正本。山札・手札・捨て札・効果処理中・選択ドロー候補・自領地を合算する。手札からの侵略／移動侵略の戦闘参照は再加算しない。旧形式の風の回廊戦闘だけは戦闘側で保持しているクリーチャーを加える。進化は枚数を維持して現在のカードIDへ置き換える。
- 未確定のランダムドロー候補、未購入の商品、他プレイヤーのカードは含めない。廃棄は `exileList` として通常一覧と別集計。同名カードは1枚ずつ保持する。
- `inventoryList` が欠けたときに手札・山札・捨て札のみで代用しない。空配列は0枚、欠落・未知カードIDは取得不備として扱う。
- `GET /api/state?room=…&me=…` は本人向け `publicState` を返す読み取り専用API。`Cache-Control: no-store`、ルーム不在404、無効な参加者／BOT403。読み取りでゲーム状態・更新番号・保存データを変更しない。既存の参加者識別方式を用いる。
- SSE、`choose` 成功応答、GETの受信処理を共通化。同じ `stateInstanceId` では新しい `stateRev` のみ採用し、古い応答・重複通知で巻き戻したり獲得演出を再生したりしない。
- `stateInstanceId` は生成・セーブ復元ごとに新規発行する実行時専用値で、保存しない。別実行への切替はGET成功時に確定し、旧接続と描画キャッシュを破棄。接続世代・ルーム・参加者が変わる前の応答は採用しない。
- デッキを開くたびにGET成功を待つ。短い読み込み表示中も×は使用可能。失敗時は「取得できませんでした」と再取得ボタンを表示し、古い一覧を出さない。
- 一覧表示中は5秒間隔、アプリ復帰時、通信復旧時に再取得。閉じている間・バックグラウンドでは定期取得を停止。同時GETは1本、タイムアウト8秒。表示中の失敗では一覧を残し「更新できませんでした」と再取得ボタンを表示する。
- 操作応答が不明な場合もGETで確認し、操作を自動再送せず確定済みの状態へ追従する。カードをクライアント側の推測で追加しない。
- 一覧と集計は同じスナップショットから描画し、内容が同じ場合はDOMとスクロール位置を維持する。描画キャッシュキーは描画完了後に更新する。画像失敗でもカード枠・名前・枚数を残す。

追加検証：`npm run test:deck-inventory`（カードID別枚数と実処理の遷移）、`npm run test:deck-sync-browser`（API・失敗・復元・通知欠落・定期取得）、`npm run test:random-draw-inventory-browser`（城・祠・戦果の実選択／取得API／一覧、応答欠落と順序逆転）。既存カード選択・デッキ・保存復元テストと `npm test` も必須。Android実機の回線切替はエミュレーションとは別に確認状況を報告する。
