# SUMMONS CODE 公式ホームページ デザイン仕様

## 1. 目的

8月31日のアーリーアクセス公開に向けて、初見のユーザーが短時間で次の3点を理解し、そのままゲームを始められる公式ホームページを作る。

1. テレビとスマホを使って遊ぶ、2〜4人向けのボードゲームであること
2. すごろく、領地争い、デッキ構築が一つになったゲームであること
3. インストール不要で、テレビ側の「ゲームを始める」から参加できること

公開表記は **SUMMONS CODE** に統一する。「Summons Crest」「クレストサーキット」は公開ページに使用しない。

## 2. ブランドコンセプト

**ボードゲーム × カードゲーム**

テレビに盤面を映し、スマホをコントローラーにして遊ぶ。ゲームシステムは「ボードゲーム × デッキ構築ローグライク」とし、周回中にカードを集め、領地を侵略・防衛する「運 × 戦略」を具体的に伝える。

画面全体は「古いタロットカード」「魔術書」「金属装飾」を基調にしつつ、情報設計は現代的で読みやすくする。ゲーム画面そのものの濃紺・金・羊皮紙の世界観を引き継ぎ、一般的なソーシャルゲーム風の発光UIには寄せない。

### デザイン原則

- **盤面を主役にする**: ファーストビューではロゴだけでなく、共有盤面とスマホで遊ぶ体験を伝える。
- **装飾より理解を優先する**: タロット装飾は見出し、区切り、カード外枠に限定する。
- **静かな高級感**: 金色は強調箇所だけに使い、全面を金色にしない。
- **ゲームへの距離を短くする**: 主要CTAは常に「ゲームを始める」。説明を読まなくても開始できる導線を置く。
- **実物を見せる**: キャラクター、スペル、クリーチャーは実装済みアセットを使い、Web専用の別世界観を作らない。
- **明朝体をブランドの声にする**: 見出し、本文、ナビゲーション、ボタンまで明朝体を基本とする。
- **英語見出しはグラフィックとして作る**: 各章の英語見出しは画像生成した専用アセットを使用し、サイト固有の表情を出す。

## 3. 推奨ページ構成

### 3.1 グローバルヘッダー

- 左: SUMMONS CODEロゴ
- 右: 「遊び方」「カード」「召喚士」「更新情報」
- 最右: 主要CTA「ゲームを始める」
- スマホではロゴ、CTA、メニューボタンの3要素に縮約する

### 3.1.1 右下固定ゲームメニュー

全ページの右下に、SuperNovaの固定メニューを参考にした円形のゲーム導線を配置する。

- 主表示: `GAME START`
- 補助表示: `ゲームを始める`
- クリック先: ゲーム画面の正式URL（実装時に `/play` を割り当てる）
- 外周: ゆっくり回転するクレストまたは属性環
- ホバー: 金色の光量を上げ、中央の矢印を4px移動
- スマホ: 画面右下から16px、直径72pxまで縮小
- メニュー展開中やCookie表示時にも主要UIを隠さない
- キーボードフォーカスと `aria-label="ゲームを始める"` を付ける

### 3.2 ファーストビュー

- 背景: `summoner-select-bg-v1.png`を暗く抑えて使用
- 中央: 明背景では `summons-code-blue.svg`、暗背景では `summons-code-gold.svg`
- 見出し: 「ボードゲーム × カードゲーム」
- 補足: 「テレビに盤面を映し、スマホをコントローラーにして遊ぶ、2〜4人用ゲーム」
- 主要CTA: 「ゲームを始める」→ `/play`
- 副CTA: 「遊び方を見る」→ `#how-to-play`
- アーリーアクセス表示: 「EARLY ACCESS — 2026.08.31」

ファーストビューはPCで720〜900px程度。ロゴ・説明・CTAがスクロールせず見えることを優先する。

### 3.3 体験説明

3枚のカードでゲームの特徴を説明する。

1. **テレビに広がる共有盤面** — 移動、領地、戦闘、演出を全員で見る
2. **スマホで手札を見る** — スマホをコントローラーにして、カード・サイコロ・領地を操作
3. **毎回変わるデッキと戦略** — 召喚、進化、スペルを獲得して構築する

### 3.4 遊び方

番号付きの4ステップにする。

1. テレビやPCでゲームを開く
2. 画面のQRコードをスマホで読み取る
3. 召喚士を選び、2〜4人でゲーム開始
4. 総資産を高め、城へ帰還して勝利

「アプリのインストール不要」「同じWi-Fiでなくても参加可能」を補助情報として明示する。

### 3.5 カードと戦略

- クリーチャー、スペル、ウェポンの3カテゴリ
- カードアートを3〜5枚だけ大きく見せる
- 全件一覧は別ページまたはモーダルへ分離する
- カード名、役割、短い効果だけを表示し、数値詳細でファーストページを埋めない

### 3.6 召喚士

- 8人を横スクロールまたは2×4グリッドで表示
- 各カードに名前、プレイ傾向、必殺技の短い説明
- 人物は `summoner-still-*.webp` を使用する
- キャラクターごとの色をアクセントに使うが、カード外枠は共通化する

### 3.7 アーリーアクセス案内

- 公開日
- 対応環境: 最新のChrome、Edge、Safari
- 開発中であること、バランスや演出が更新されること
- フィードバック導線（URL決定後に接続）
- セーブはテレビ側ブラウザに保持される旨

### 3.8 最終CTAとフッター

- 見出し: 「盤面を開き、召喚を始めよう。」
- CTA: 「SUMMONS CODEを遊ぶ」
- フッター: 遊び方、更新情報、問い合わせ、権利表記

## 4. レスポンシブ方針

- 主要ブレークポイント: 1200px / 768px / 480px
- 本文最大幅: 1120px
- スマホでは2カラム以上を使わず、カードは横スクロールまたは1カラムにする
- CTAの最小タップ領域は44×44px
- 本文は16px未満にしない
- タロット枠線は小画面では簡略化し、情報量を減らす
- 画像には固定高さと `object-fit` を指定し、レイアウトシフトを防ぐ

## 5. モーション

- 初期表示: 600ms以内のフェードと小さな上方向移動
- カードホバー: 2〜4pxの浮上と金縁の明度変化
- 背景: 非常に遅い拡大または光の移動のみ
- ゲーム本編の必殺技・召喚演出をホームページで再現しない
- 自動再生動画をファーストビューの必須要素にしない
- 右下ゲームメニューの外周装飾は24〜40秒で一周させる

## 5.1 画像生成する英語見出し

以下の見出しを、透過背景のWebPとして同一シリーズで制作する。

- `CONCEPT`（採用A案: ロゴ準拠の単色シルエット）
- `PLAY STYLE`
- `HOW TO PLAY`
- `GAME SYSTEM`
- `SUMMONERS`
- `CARDS`
- `EARLY ACCESS`
- `NEWS`

共通仕様:

- 高コントラストなセリフ体を核にした、古いタロット印刷風の文字
- アイボリーを主色、儀式金を部分的な差し色にする
- 文字の一部へクレスト、星、軌道、カードの切れ目を融合する
- 背景は完全透過
- 横長、左右に十分な余白、4K幅で生成してWebPへ縮小
- ピンク、ネオン、SF端末風、読めない過剰装飾は避ける
- 画像の直下または視覚的に非表示のHTML見出しを残し、読み上げとSEOを担保する

## 6. アクセシビリティ

- 本文と背景のコントラスト比4.5:1以上
- 金色だけで状態を表さず、文言・形・アイコンを併用する
- キーボードフォーカスを常に可視化する
- 装飾画像は空の代替テキスト、意味を持つ画像は具体的な代替テキストを付ける
- 見出し階層は `h1` → `h2` → `h3` の順を守る
- ユーザーの `prefers-reduced-motion` ではWebサイト側の装飾モーションを停止する

## 7. 実装時の完了条件

- 3秒以内に「どんなゲームか」「何人で遊ぶか」「どう始めるか」が分かる
- PCとスマホの両方で主要CTAがファーストビューに見える
- 既存ゲームの色・ロゴ・キャラクターと一貫している
- LighthouseのPerformance / Accessibility / Best Practices / SEOを各90以上の目標とする
- Open Graph画像、タイトル、説明文、faviconを設定する
- ゲーム本体へのリンク切れがない
