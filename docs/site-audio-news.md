# 公式サイトのBGMと更新情報

## BGM

トップ、カード、ルール、更新情報一覧、個別記事で `site-audio.js` / `site-audio.css` を共用する。ゲーム・スマホ操作・開始ガイドには読み込まない。

- 音源はゲームタイトルと同じ `/assets/bgm_select.mp3`。音量0.35、ループ。ON操作まではAudioの生成・音源のリクエストを行わない。
- `localStorage.sc_site_audio_v2` に `choice`（on/off）を保存し、同じオリジンの全タブで共有する。再生位置（秒）だけは `sessionStorage.sc_site_audio_position_v2` にタブ単位で保存する。ゲーム側の `sc_board_audio_v1` とは独立。
- 旧 `sessionStorage.sc_site_audio_v1` は共有設定がまだないときだけ移行する。共有設定がOFFなら、古いタブのONより優先する。保存不可なら同一ページ内で動作し、別ページ・別タブへの保持は保証しない。
- ON/OFFを書き込むのは明示操作と初回移行のみ。再生位置の保存・非表示・ページ終了時にON/OFFを書き戻さない。
- 別タブからのOFFは `storage` イベントで停止・表示へ反映する。イベントの古い値ではなく保存先の最新値を読む。別タブからのONは設定を共有するが、自動では再生開始せず、再開操作またはページ復帰時に再生を試みる。
- ページ移動時・非表示時に停止。表示復帰・フォーカス・履歴からの復元時は保存先を読み直し、ONの場合だけ続きから再生を試みる。遅れて再生Promiseが完了しても、最新設定がOFFなら停止。再生拒否時は「BGMを再開」から再試行できる。
- 初回選択はネイティブdialogでフォーカスを囲み、閉じるとmainへ戻す。EscapeはOFFとして入る。

## 更新情報

`site-news.js` の4件の共通データからサーバー側で行を生成する。トップは最新3件、`/news` は全件。`?category=notice|update` で絞り込み、不明な値は全件表示。日付が同じ場合はデータ内の順序を維持する。

タイトル・日付・カテゴリ・URLを共通データで管理し、個別記事本文はHTMLに置く。記事追加時は一覧データ、記事HTML、サーバールートを追加する。バグ修正記事の既存URLと本文は保持する。

HTMLのETagには一覧データとカテゴリも含める。サーバー側で出力するため、JavaScriptが無効でも最新情報・絞り込み・記事リンクを利用できる。

## 検証

- `npm.cmd test`：既存のゲーム、ホームページ、記事、計測、フィードバックの回帰確認。
- `npm.cmd run test:site-audio-news`：PlaywrightとChromeを使用。必要に応じてNODE_PATHをPlaywrightのインストール先へ設定する。
- `npm.cmd run test:site-audio-sync`：新規/既存/再作成タブの共有OFF、通常遷移・戻る・古いON状態の復元、旧設定移行、再生Promiseの遅延、保存拒否を確認。
- 実音源の再生、OFF時の音源リクエストなし、再生位置の引継ぎ、非表示時停止、再生拒否後の再試行、保存不可、フォーカス、320px以上のヘッダー、カテゴリとキャッシュ、JavaScript無効時の閲覧を確認する。
- 画面キャプチャは `output/site-audio-news/`。音声の聴感やSafari実機での再生は別途確認する。

本作業はローカル実装まで。コミット・本番反映は別途依頼時に行う。
