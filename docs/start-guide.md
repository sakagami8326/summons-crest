# ゲーム開始案内

## 入口と表示条件

- `/play` はPC・テレビで盤面を表示し、初回だけ開始案内をダイアログ表示する。
- スマホは `/start?entry=1` に移動する。`screen=board` を指定してもスマホで盤面は表示しない。
- スマホの最初の案内は「ゲームはPC・テレビで開いてください」を大きく表示し、盤面＋各自のスマホ、盤面のQRをカメラで読み取る図で役割を説明する。「PC・テレビの準備方法を見る」から環境選択へ進む。図のQRは説明用で、参加に使うのは実際の盤面に表示されたQR。
- タブレットは盤面用／操作用を選ぶ。`sessionStorage.sc_screen_role_v1` にタブ内の役割を保持する。盤面用は `/play?screen=board`。操作用は `/phone`。
- `/phone?room=…` は従来どおりQRのルームを優先し、説明を自動表示しない。`/phone` のヘルプは明示操作で開く。
- `localStorage.sc_start_guide_v1=done` は説明全体の完了・スキップで保存する。タイトルとロビーからいつでも再表示できる。保存が利用できない場合も、その場でタイトルへ進める。
- `/start?method=pc|pc-tv|fire-tv|google-tv` は方法別の説明への直接リンク。不明なmethodは3択に戻す。

## 案内の構成

1. 環境を選ぶ：PC単体／PCをテレビ・モニター・スクリーンに映す／Fire TV・Google TV。
2. ルーム作成：通常2〜4人、BOT戦は1人＋BOT。マップを選ぶ。
3. 参加：各自のスマホでQRを読むか、4文字コードを入力し、名前を入力して参加。
参加画面に、スマホを横向きにして召喚士を確定し、盤面側でゲーム開始する旨を簡潔に併記する。召喚士選択の独立した説明画面は設けない。

PC単体は環境選択からルーム作成へ直接進む。ブラウザを開く・URL入力・タイトル確認のスライドは設けない。
PCの外部画面はテレビ・モニターとプロジェクターに分岐し、ケーブル、入力切替、Windowsの複製／Macのミラーリングを案内してルーム作成へ進む。
テレビブラウザはFire TV（Silk）とGoogle TV（TV Bro）に分岐する。双方ともゲーム動作は実機未確認。ユーザーの表示調整指示により「ゲーム動作確認中」ラベルは掲載しない。UAを模擬したブラウザ試験は実機試験の代わりではない。

## 実装と画像

案内は `public/start.html` と `public/assets/start-guide/` に集約。盤面・手元では同一オリジンの案内iframeを必要時にだけ開き、閉じるメッセージの送信元・originを検証する。閉じた後は元のボタンにフォーカスを戻す。

機器図は軽量なインラインSVGであり、設定画面の再現ではない。タイトル画像は今回のローカル実装を撮影してWebP化したもの。QR説明の画像は既存のホームページ素材を共用する。未選択の方法の画像を先読みしない。

## 検証

- `npm run test:start-guide`：端末判定、HTTPルーティング、キャッシュ分岐、軽量な案内の配信。
- `npm run test:start-guide-browser`：PlaywrightとChromeが必要。既存のv158ブラウザ試験と同様に、必要に応じてNODE_PATHにランタイムのnode_modulesを指定する。
- ブラウザ試験では初回・再訪・再表示、3択と分岐、フォーカス・矢印キー、320px幅、スマホ縦横、タブレットの役割変更、iPadのPC形式UA、保存・コピー不可、QR・手動参加、通常対戦・BOT戦の試合開始、復帰・別QR・無効ルームを検証する。
- スクリーンショットは `output/start-guide/` に保存する。実機Fire TV／Google TV、実際の映像ケーブル接続、初見ユーザーによる操作確認は別途必要。

ゲーム進行・ルームAPI・既存セーブ形式は変更しない。本変更だけでは公開されず、コミット・本番反映は別途行う。
