## 0. 本書の目的

本書は、Phaser 4へ移行済みの共有TV盤面について、今後採用する演出と実装範囲を実装者へ伝える発注書である。

既存のPhase 2A〜2Eで実装済みの以下は維持する。

- 優先度付きPresentationQueue
- `PW.play()`によるEffectDirector
- EffectPool
- High / Standard / Lite品質設定
- 演出低減設定
- コマ移動のsquash & stretch
- 召喚・強化・進化・退場FX
- 通行料コイン
- 連鎖発光
- 呪い・結界FX
- 侵略成功・防衛成功後の盤面FX
- Phaser失敗時のDOMフォールバック

今回の発注では、これらを土台として次の5項目を追加・刷新する。

1. クリーチャー配置時の演出強化
2. 土地レベルに応じたマスデザインの段階変化
3. 強化可能領地・選択中候補のハイライト
4. 全22種のスペルを盤面上の出来事として表現
5. Phaser＋DOMのハイブリッド戦闘
6. 最終城通過時の勝利演出

## 1. 確定方針

### 1.1 クリーチャー区分

本ゲームには「大型クリーチャー」というシステム上の区分を設けない。

- すべてのクリーチャーは共通の表示・演出基盤を使用する。
- 特定クリーチャーだけを大型扱いして演出品質・表示倍率・素材仕様を分岐させない。
- クリーチャー固有差が必要な場合は、既存の共通モーションProfileと属性エフェクトのパラメータ差で表現する。
- 全クリーチャーをパーツ分けする前提にしない。
- 原則として完成済みの一枚絵を使用する。

### 1.2 常時演出

以下は実装しない。

- クリーチャーの待機モーション
- クリーチャー固有の常時オーラ
- 土地の常時パーティクル
- 盤面全体の常時アニメーション
- Camera演出パターンの追加
- ゲーム終盤の常時ライティング変化

盤面がうるさくならないよう、平常時は静止を基本とする。

### 1.3 属性エフェクト素材

属性エフェクト素材は発注者側で準備し、実装者へ支給する。

- 実装者は属性エフェクトの新規アート制作を担当しない。
- 素材到着前は既存Graphics・仮粒子で接続と動作を実装してよい。
- 素材到着後、同じイベント契約のまま画像素材へ差し替える。
- 素材の有無でゲーム進行を分岐させない。

### 1.4 Camera

現行のCamera仕様を維持する。

- 全景
- 対象マスへのクローズアップ
- 全景への復帰
- 短いCamera shake

新しいpan、追従、複雑なカメラワークは今回の対象外とする。ただし、最終城通過演出に必要な「全景→城ズーム」は既存APIの組み合わせとして実装する。

## 2. 実装全体の共通要件

### 2.1 状態と演出の分離

- サーバー確定stateを正とする。
- Phaser演出からゲーム結果を決定しない。
- 演出失敗・タイムアウト・Lite設定でもゲーム進行を継続する。
- 同じイベントの二重再生を防止する。
- SSE再接続時は古い演出を破棄して最新stateへ同期する。

### 2.2 演出順

既存PresentationQueueを使用する。

優先度:

1. 戦闘・勝利
2. 召喚・進化・退場・土地変化・スペル
3. 経済・連鎖
4. 補助表示

- TURN STARTは優先度1〜3の完了後に表示する。
- 同じイベント内の複数Tween・粒子は並列再生可能。
- 別イベントは直列にする。

### 2.3 品質設定

既存のHigh / Standard / Liteを維持する。

| 設定 | 画像FX | 粒子 | Filter | Camera shake |
|---|---|---|---|---|
| High | 100% | 100% | 許可 | 標準 |
| Standard | 100% | 60〜70% | 必要最小限 | 弱 |
| Lite | 必須の大形状のみ | 20〜30% | 原則なし | なし |

- 既定はStandard。
- 品質が異なっても演出の意味と結果表示を変えない。
- 演出低減設定では全画面フラッシュとCamera shakeを抑制する。

### 2.4 視認性

- クリーチャーの顔とシルエットをエフェクトで長時間隠さない。
- 通常時は盤面を静止させ、イベント発生地点だけを動かす。
- 同時に複数マスを強く点滅させない。
- 強い白発光は100ms前後の命中瞬間に限定する。
- 文字・数値・説明はDOMを優先する。

## 3. 支給する属性エフェクト素材の仕様

### 3.1 配置先

推奨配置:

```text
public/assets/fx/
├─ common/
├─ fire/
├─ water/
├─ earth/
├─ wind/
└─ neutral/
```

実装者は、最終的な配置先を既存アセット管理方式に合わせて調整してよい。ただし、クリーチャー画像やUI画像と混在させず、`fx`配下へ集約する。

### 3.2 最低限の素材種別

属性ごとに次の素材を支給予定とする。

| キー | 用途 |
|---|---|
| `particle_01`〜`particle_04` | 小粒子、破片、水滴、火花など |
| `trail_light` | 細い移動・攻撃軌跡 |
| `trail_heavy` | 太い攻撃軌跡 |
| `impact_small` | 小命中 |
| `impact_large` | 通常戦闘命中 |
| `summon` | 配置・召喚の中心エフェクト |
| `disperse` | 退場・解除 |

共通素材:

| キー | 用途 |
|---|---|
| `flash_soft` | 局所白発光 |
| `shockwave` | 命中時の円形衝撃 |
| `glow_round` | 選択・強化 |
| `spark_gold` | レベルアップ・勝利 |

### 3.3 ファイル要件

- 透過PNGまたは透過WebP
- sRGB
- 文字・数字・ロゴなし
- 接地影なし
- 背景なし
- 不要な透明余白を削除
- 回転使用する素材は方向依存を避ける
- 発光素材は暗背景で確認する
- Lighten/Add系Blend Modeで破綻しない
- 素材自体に黒い矩形背景を含めない

スプライトシートの場合:

- 全コマ同一サイズ
- 左上から右方向へ再生
- フレーム数とFPSをメタデータへ記録
- 最終コマは完全透明または自然に消える状態

### 3.4 マニフェスト

素材のファイル名をゲームロジックへ直接散在させず、マニフェストで管理する。

例:

```js
const FX_ASSETS = {
  water: {
    particles: [
      '/assets/fx/water/particle_01.png',
      '/assets/fx/water/particle_02.png'
    ],
    trailLight: '/assets/fx/water/trail_light.png',
    trailHeavy: '/assets/fx/water/trail_heavy.png',
    impactSmall: '/assets/fx/water/impact_small.png',
    impactLarge: '/assets/fx/water/impact_large.png',
    summon: '/assets/fx/water/summon.png',
    disperse: '/assets/fx/water/disperse.png'
  }
};
```

- 素材未配置時は既存Graphicsへフォールバックする。
- 欠損素材でSceneを失敗させない。
- 属性ごとの実装コードを複製せず、共通関数へ属性キーを渡す。

## 4. クリーチャー配置時の演出強化

### 4.1 対象

- 空き地への通常召喚
- 交代による新クリーチャー配置
- 移動スペルで空き地を領地化した場合
- その他、盤面上へ新しいクリーチャーが現れる処理

侵略成功後の配置は既存`invade-fx`を使用し、同じ召喚演出を重ねて二重再生しない。

### 4.2 シーケンス

1. 対象マスを既存Cameraでクローズアップする。
2. マス中央に属性色の波紋または召喚紋を表示する。
3. マス外周から中心へ属性粒子を収束させる。
4. クリーチャーをAlpha 0、Scale 0.80で表示する。
5. 180〜260msでAlpha 1、Scale 1.05へ変化させる。
6. 120〜180msでScale 1.00へ戻す。
7. 着地時に支給された属性`impact_small`または`particle`を外側へ出す。
8. 土地所有色とクリーチャー表示を確定する。
9. 既存の中央下メッセージまたは召喚DOMカットインを表示する。

### 4.3 演出時間

- Phaser盤面側: 0.8〜1.2秒
- DOM召喚カットインと並列可能
- 全体のゲーム進行待機時間を現行より1秒以上延長しない

### 4.4 制限

- 配置後の待機モーションは付けない。
- 配置後の常時オーラは残さない。
- 全クリーチャー共通の一枚絵処理とする。
- クリーチャーごとの専用コードを作らない。

### 4.5 受入条件

- 全属性で同じシーケンスが再生できる。
- 素材未着属性はGraphicsフォールバックで再生できる。
- 配置後にTween・粒子・一時Spriteが残らない。
- state更新後の正しいクリーチャー画像が最終的に表示される。

## 5. 土地レベル別マスデザイン

### 5.1 目的

土地レベルを数字だけでなく、80px程度の縮小表示でも外形と大きな装飾差で判断できるようにする。

常時アニメーションは追加せず、静止デザインとして豪華さを段階化する。

### 5.2 実装方式

- 現行`buildTileSVG()`を拡張する。
- Lv1〜Lv4ごとにSVGの構造を分岐する。
- 属性・所有者色・結界・呪い・通行料など既存表示と共存する。
- レベルごとに個別のラスター画像を28マス分用意しない。
- DOM描画とPhaser描画で同じSVG生成関数を使用する。

### 5.3 レベル差

#### Lv1

- 現行に近い石板
- 細い所有者色の外周
- 小さな属性ルーン
- 装飾最小

#### Lv2

- 外周を一段補強
- 四隅に小さな石または金属装飾
- 属性ルーンをLv1より約15%大きくする
- 所有者色の面積を少し増やす

#### Lv3

- 二重外周
- 中心ルーンをLv2より大きくする
- クリーチャー下に静止台座または紋章面を追加
- 白金または鈍い金色の細い縁
- 進化が発生する重要レベルとして一目で分かる形

#### Lv4

- 最も厚い外周
- 四隅に大形状の装飾
- 中心紋章を最大化
- 所有者色、属性色、金属色の3層
- 通行料タグと競合しない範囲で上位フレーム
- Lv3との差を模様の細かさではなく、外形と面積で出す

### 5.4 属性差

| 属性 | 外形・装飾 |
|---|---|
| 火 | 尖った角、割れ目、上向き形状 |
| 水 | 丸み、波形、流線 |
| 土 | 厚い石、角柱、重量感 |
| 風 | 細長い角、翼状、抜け |
| 無 | 左右対称、幾何学 |

属性差を細かな模様だけで表現しない。

### 5.5 受入条件

- 色を外してもLv1〜Lv4を外形で判別できる。
- 1280×905と実TVの両方で差が見える。
- クリーチャー、コマ、建造物、通行料タグを隠さない。
- DOM版とPhaser版で形状が一致する。
- 結界・呪い表示が埋もれない。
- 既存fixtureで全レベルを比較できる。

## 6. 強化可能領地・選択候補ハイライト

### 6.1 強化可能領地

強化選択中のみ表示する。

- 強化可能な自領地すべてへ細い金色の外周を表示
- Alphaを0.45〜0.80の範囲で1.2〜1.8秒周期に変化
- クリーチャーより背面、マスタイルより前面
- 他プレイヤー領地と強化不可能領地は発光させない
- 選択画面終了時に即時除去

### 6.2 選択中候補

スマホで現在選択・プレビューしている1マスだけを一段強く表示する。

- 二重外周
- Alpha 0.9以上
- 中心ルーンの明度上昇
- クリーチャー下から弱い金色発光
- Lv3到達で進化する場合は短い光柱予告または進化マーク
- 点滅速度を上げず、外周の太さと明度で差を出す

### 6.3 プレビュー通信

現行stateが候補一覧しか持たない場合、選択中の1マスをTVへ伝えるため、一時的なプレビューイベントを追加する。

要件:

- セーブデータへ保存しない。
- ゲームルールへ影響しない。
- スマホから候補をタップした時だけ送信する。
- SSEでTVへ通知する。
- 決定、キャンセル、手番変更、切断時に解除する。
- 送信可能なtileが現在の強化候補に含まれることをサーバーで検証する。
- 他プレイヤーが偽のtileを送っても表示しない。
- 連続タップは100〜150ms程度で抑制してよい。

推奨イベント:

```text
POST /api/upgrade-preview
{ roomCode, playerId, tile }

publicState.presentation.upgradePreview
{ playerId, tile, at }
```

名称と経路は現行サーバー構成に合わせて変更可。ただし永続game stateとは分離する。

### 6.4 受入条件

- 強化画面を開くと正しい候補だけが弱く発光する。
- スマホで候補を変えるとTVの強調マスが追従する。
- キャンセル後にハイライトが残らない。
- 別プレイヤーからの不正previewを受理しない。
- DOM描画時も最低限の候補表示を維持する。

## 7. スペル盤面演出

### 7.1 目的

TVを見る全員が、誰が、どのマスへ、どの効果を使い、何が変わったかを理解できるようにする。

既存のスペルバナーは維持し、盤面FXだけで効果説明を完結させない。

基本順:

```text
スペル名バナー
→ 対象マス表示
→ 盤面FX
→ state反映
→ ダメージ・回復・レベル・移動など結果表示
```

### 7.2 共通プリミティブ

個別スペルごとに独立した実装を作らず、次を共通化する。

| プリミティブ | 用途 |
|---|---|
| `projectile` | 術者側または画面外から対象へ飛ばす |
| `impact` | 対象マスで着弾 |
| `area` | 対象マスを囲む継続効果 |
| `link` | 2マスを接続 |
| `moveCreature` | クリーチャーを別マスへ移動 |
| `swapCreatures` | 2体を同時に入れ替え |
| `pulse` | 回復・強化・弱体 |
| `crack` | レベル低下・岩盤 |
| `attributeChange` | タイル属性の切替 |
| `disperse` | 帰還・解除・退場 |
| `hudTransfer` | 金・ドローなど盤面外への移動 |

### 7.3 全22種の演出割当

#### 黄金の呪文

- プレイヤーコマまたは城付近に金色ルーン
- 金粒子がHUDへ移動
- 獲得額はDOM表示

#### ダブルドロー

- コマ付近に白金色の閃き
- カード裏面2枚がHUD方向へ移動
- カード内容はTVへ表示しない

#### 羽休め

- 対象クリーチャーを風または羽状光で包む
- 縮小・上昇・消滅
- 土地が空き地へ変化

#### 衰弱の呪文

- 暗紫色projectile
- 対象で着弾
- クリーチャーを短く紫Tint
- `−20`または軽減後の値をDOM表示
- 撃破時は既存`ruin-fx`へ接続

#### 疾風の呪文

- コマ周囲へ短い旋風
- ダイス演出開始前に風線を表示
- ダイス2個であることは既存DOMで伝える

#### 風向転換

- コマ周囲に一周する風
- 盤面外周へ短い逆方向矢印または風の流れ
- 絵文字は使用しない

#### ムーブ

- 移動元と移動先を細い属性線で接続
- クリーチャーを線に沿って移動
- 空き地なら配置演出へ接続
- 敵地なら戦闘へ接続

#### 風の回廊

- 2マスへ同一の風紋
- 太い風の帯で接続
- クリーチャーを帯に沿って移動
- 生還時は羽休めに近い帰還演出

#### スイッチ

- 2マスへ同一魔法陣
- 2体を同時に縮小
- 交差する光跡
- 入れ替え先で再出現
- 負傷表示もstateと一致させる

#### チェンジ

- 旧クリーチャーを暗転・縮小して捨て札方向へ消す
- 新クリーチャーを通常配置演出で出現
- 2演出を直列化

#### 血染めの刃

- 使用プレイヤーまたは次の侵略候補へ暗赤色の刃エフェクト
- 次の侵略まで残る状態表示は小さな静止アイコン
- 侵略開始時に刃エフェクトを攻撃へ合流

#### 炎の渦

- 小さな火種projectile
- 対象マスで円形の炎
- 10ダメージ表示
- 次の侵略まで小さな静止状態表示

#### 根の牢獄

- 対象マス四隅から根が中心へ伸びる
- 侵略AT−20を示す静止リング
- 効果消費時に根が砕けて消える

#### 岩盤隆起

- タイル外周へ亀裂
- 岩片が下から上へ移動
- クリーチャーに回復pulse
- DF+10の静止状態表示

#### 満ち潮

- 対象水領地の外周へ一周する波
- 水滴が通行料タグへ集まる
- 効果中は小さな静止水紋

#### 加護の呪文

- 自領地を盤面順に弱く発光
- 各マスへ結界輪を表示
- 常時状態は既存結界枠を使用
- 侵略阻止時は既存`barrier-flash`

#### 地割れの呪文

- 対象マス中央から外周へ亀裂
- 岩片と砂煙
- レベル段積みを1段沈める
- 新レベルのSVGへ切替

#### 豊穣の角

- 自領地を盤面順に金緑色でpulse
- 各領地から小さな光がHUDへ集まる
- 合計金額をDOM表示

#### フレイム・シフト

- 対象タイル中心に火種を埋める
- 外周へ赤い亀裂
- 光で一度覆ってから火属性SVGへ切替

#### アクア・シフト

- 水球が対象へ落ちる
- 波紋で一度覆ってから水属性SVGへ切替

#### アース・シフト

- 岩片が対象中心へ集まる
- 土煙で一度覆ってから土属性SVGへ切替

#### ウィンド・シフト

- 結晶片が上空から集まる
- 風で一度覆ってから風属性SVGへ切替

### 7.4 属性変更の注意

- `TILES`を直接変更しない。
- 現行仕様どおり`r.elemOv`と`tileElem()`を使用する。
- stateが先に切り替わる場合は、旧タイルSVGを一時Spriteとして保持し、エフェクト中に新SVGへ切り替える。
- 連鎖変化は属性変更FX終了後に既存`chain-glow`へ接続する。

### 7.6 受入条件

- 対象ありスペルは対象マスを誤認しない。

- 属性変更後の連鎖・地価計算へ影響を与えない。
- 秘密のカード内容をTVへ表示しない。

## 8. Phaser＋DOMハイブリッド戦闘

### 8.1 目的

現行DOM戦闘の情報量と可読性を維持しながら、クリーチャーの攻撃・属性・命中・退場をPhaserで表現する。

### 8.2 分担

| Phaser | DOM |
|---|---|
| クリーチャー本体 | プレイヤー名 |
| 予備動作・踏み込み | クリーチャー名 |
| 属性攻撃 | AT / DF |
| 命中・反動 | HPバー・HP数値 |
| ヒットストップ | 支援カード |
| 退場・帰還 | 効果注記 |
| 局所発光・shake | 侵略成功・防衛成功 |

DOM側の情報をCanvasへ移植しない。

### 8.3 BattleScene

- 盤面Sceneとは別の`BattleScene`を使用する。
- 戦闘オーバーレイ内にPhaser CanvasまたはScene表示領域を置く。
- 戦闘開始時だけ起動・表示する。
- 盤面stateの受信は継続する。
- 戦闘中の盤面演出はPresentationQueueで保留する。
- 戦闘終了時に最新stateを盤面へ反映する。
- BattleScene失敗時は現行DOM戦闘へ切り替える。

### 8.4 一枚絵モーション

全クリーチャー共通で次を使用する。

- Position Tween
- Scale X / Y
- Rotation
- Alpha
- Tint / Phaser 4 Filter
- 短い残像

腕、脚、武器を個別に動かす前提にしない。

基本シーケンス:

1. 予備動作
2. 踏み込み
3. 属性trail
4. impact
5. 50〜90msのヒットストップ
6. 防御側の反動
7. HP更新
8. 撃破または反撃

### 8.5 モーションProfile

「大型」という区分を設けず、攻撃方法だけをProfile化する。

| Profile | 主な対象 | 動き |
|---|---|---|
| `melee` | 近接型 | 後ろへ引く→前進→命中 |
| `charge` | 突進型 | 低く構える→直線突進 |
| `caster` | 魔法型 | 収束→遠隔projectile |
| `weapon` | 剣・槍型 | 武器起点のtrail |
| `beast` | 四足・獣型 | 全身の短い踏み込み |
| `floating` | 霊体 | 浮上→遠隔攻撃→反動 |

Profileは見せ方のみを変更し、AT・攻撃順・結果へ影響しない。

### 8.6 属性Profile

共通:

```text
charge
→ trail/projectile
→ impact
→ particle
→ fade
```

- 火: 直線または爆発
- 水: 曲線水流または波
- 土: 岩・亀裂・重量衝撃
- 風: 高速軌跡・真空刃
- 無: 幾何学光・静かな衝撃

固有能力は共通素材のScale・速度・回数・発生位置で表現する。

### 8.7 戦闘分岐

必須対応:

- 攻撃側が一撃で勝利
- 防御側が生存して反撃
- 反撃で攻撃側撃破
- 攻撃側が反撃を耐えて帰還
- 防御側【先制】
- 攻撃側【双撃】
- 支援カードあり・なし
- 支援無効化
- ダメージ0
- 防御側残HP1以上

### 8.8 最初の縦切り

最初に次だけを完成させる。

- 水属性攻撃側
- 土属性防御側
- 支援カードなし
- 通常1回攻撃
- 侵略成功
- 防衛成功＋反撃

この縦切りの受入後、他属性・先制・双撃・支援カードへ展開する。

### 8.9 演出時間

- 一撃決着: 6〜8秒を目安
- 反撃あり: 8〜11秒を目安
- 現行DOM戦闘より大幅に長くしない
- ヒットストップでJavaScriptやSSE処理を停止しない
- 演出Tweenまたは専用タイムラインだけを一時停止する

### 8.10 受入条件

- 現行DOM戦闘と同じ数値・結果を表示する。
- クリーチャーを再デザインせず既存一枚絵を使用できる。
- 全戦闘分岐を再生できる。
- 演出失敗時に現行DOM戦闘へ復旧できる。
- Standard品質で実TV上30fps未満が継続しない。
- 戦闘終了後に一時オブジェクト・Tween・Filterが残らない。
- TURN STARTが戦闘へ割り込まない。

## 9. 最終城通過・勝利演出

### 9.1 発動条件

- 勝利条件を満たしたプレイヤーが城を通過し、サーバーがゲーム終了を確定した場合
- 演出は確定済み結果を再生するだけとする

### 9.2 シーケンス

1. コマの城到着演出を完了する。
2. 他のPresentationQueueを停止せず、勝利演出を最優先へ置く。
3. 既存Camera APIで全景へ戻す。
4. 勝者の所有領地だけを盤面順に弱く発光させる。
5. 刻印・所有色の光を城へ収束させる。
6. Cameraを城へクローズアップする。
7. 城から金色の光柱と粒子を表示する。
8. 勝者のキャラクター立ち絵をDOMカットインで表示する。
9. 勝者名と「勝利」を表示する。
10. 最終資産、領地数、称号をDOMで表示する。

### 9.3 時間

- 盤面演出: 3〜5秒
- 勝利カットイン・結果表示: 4〜7秒
- 結果画面は自動で即時消さず、ユーザー操作または既存終了フローへ接続する

### 9.4 制限

- ゲーム終盤の常時演出は追加しない。
- 勝利確定前に予告として再生しない。
- 他プレイヤーの領地を勝者色で発光させない。
- 全画面の激しい点滅を使用しない。

### 9.5 受入条件

- 全景→城ズーム→勝利カットインの順序が固定されている。
- 勝者以外の領地を誤って発光させない。
- 勝利結果と表示値がサーバーstateと一致する。
- Lite・演出低減でも全景と城ズーム、勝者表示は残る。
- DOM描画時は既存勝利画面へフォールバックする。
