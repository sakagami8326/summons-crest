# Phaser 4 盤面演出・戦闘演出 実装計画（Phase 2以降・v0.67）

作成日: 2026-07-26  
対象: Summons Crest（クレストサーキット）  
前提: `docs/spec_phaser4_migration_v0.67.md`の受入完了後  
対象Phaser: 4.2.1固定

---

## 0. 本書の位置づけ

本書は、`docs/plan_phaser_board_v0.66.md`で概要のみ定義されていたPhase 2以降を、Phaser 4を前提として再設計した後続計画書である。

v0.66のPhase 0〜1Dは「DOM盤面と同等の表示をPhaserで成立させる段階」だった。Phase 2以降は、ゲームルールを変更せず、共有TV画面で次のことを分かりやすく伝える。

- 誰が動いたか
- どこで何が起きたか
- どの属性・効果が働いたか
- 攻撃が当たったか
- 土地・クリーチャー・資産がどう変化したか
- 次に誰が操作するか

本書では、派手さそのものではなく、**ゲーム状態の変化を短く、気持ちよく、誤解なく見せること**を演出の目的とする。

## 1. Phase 2以降の基本原則

### 1.1 表示とゲーム進行を分離する

- サーバー状態を正とし、演出結果からゲーム状態を決定しない。
- Phaserは受信済みの結果を再生するプレゼンテーション層とする。
- 演出が失敗・省略されてもゲーム進行は継続できること。
- Phaser側からサーバーへ戦闘結果や所持金を送信しない。

### 1.2 スマホとTVの役割を維持する

| 画面 | 役割 |
|---|---|
| スマホ | 手札、秘密情報、カード選択、意思決定、直接操作 |
| TV・盤面 | 全員に公開される状態、移動、召喚、侵略、結果、属性演出 |

手札UIをPhaserへ移さない。Phaserの投資先は盤面・クリーチャー・戦闘・状態変化とする。

### 1.3 アートとPhaserの責務を分ける

**アートが担当するもの**

- クリーチャーの造形、頭身、シルエット
- 顔、鎧、武器、固有模様
- 本体のセル塗り、主線、基本影
- 属性を示す身体構造と固有色

**Phaserが担当するもの**

- 移動、拡大縮小、傾き、振動、残像
- 発光、色変化、Filter
- 水滴、火花、砂塵、風片などの粒子
- 波紋、斬撃、衝撃波、命中光
- Camera pan、zoom、shake
- 発生順序、速度、強弱、消滅

接地影、選択リング、攻撃軌跡、状態異常、ダメージ表現をクリーチャー本体へ焼き込まない。

### 1.4 大きなシルエットを隠さない

- 属性エフェクトはクリーチャー本体より前面・背面を使い分ける。
- 通常演出では顔と輪郭の70%以上を視認可能にする。
- 最大発光は命中の瞬間だけとし、常時白飛びさせない。
- 小粒子を大量に出すより、波紋・斬撃・衝撃波など大きな形を優先する。

### 1.5 演出は直列、内部要素は並列

既存の`cutBusy`とバナーキューの思想を維持する。

- 「召喚→進化→TURN START」のような別イベントは直列にする。
- 1つの攻撃内の「踏み込み＋水流＋Camera追従」は並列再生してよい。
- 演出完了Promiseが解決してから次のイベントを開始する。
- タイムアウトを持ち、例外時もキューを停止させない。

## 2. Phaser 4向け演出アーキテクチャ

### 2.1 構成

```text
board.html
├─ state差分検出・イベント生成
├─ 既存DOMオーバーレイ
└─ PresentationQueue
     └─ BoardWorld(PW)
          ├─ BoardScene
          ├─ EffectDirector
          ├─ EffectPool
          ├─ CameraDirector
          ├─ CreaturePresenter
          └─ QualityController
```

### 2.2 EffectDirector

個別イベントの演出順序を一元管理する。

想定API:

```js
PW.play({
  type: 'invasion-hit',
  tile: 12,
  element: 'water',
  attackerId: '...',
  defenderId: '...',
  power: 'normal',
  result: 'win'
});
```

要件:

- 呼び出し元はTween、Filter、粒子の実装詳細を知らない。
- `PW.play()`はPromiseを返す。
- 未対応イベントは即時resolveし、ゲームを止めない。
- 同一イベントIDの二重再生を防止する。
- Scene破棄、Renderer切替、SSE再接続時に安全にキャンセルできる。

### 2.3 PresentationQueue

DOM演出とPhaser演出を同じキューで扱う。

イベント優先度:

1. 戦闘・破産・勝利などゲーム理解に必須
2. 召喚・進化・退場など盤面変化
3. 通行料・連鎖など経済変化
4. 補助的な移動ジュース

要件:

- TURN STARTは優先度1〜3の完了後に表示する。
- 連続state更新で古くなった優先度4演出は省略可能とする。
- 必須演出の最大待機時間を定義し、停止時は結果表示へスキップする。
- DOMフォールバック時も同じイベント順を維持する。

### 2.4 EffectPool

頻繁に使うオブジェクトを再利用する。

対象:

- 水滴、泡、火花、砂片、風片
- コイン
- 小さな発光Sprite
- 波紋、衝撃波
- ダメージ用の短命オブジェクト

要件:

- 毎回大量のGame Objectを生成・破棄しない。
- 非表示・停止状態でPoolへ戻す。
- Pool上限を超えた演出は粒子数を減らす。
- Scene終了時にPoolを一括破棄する。

### 2.5 Phaser 4 Filterの使用方針

Phaser 4では旧FX・MaskではなくFilterを使用する。ただし、Filterを演出の土台にはせず、必要な瞬間だけ使う。

使用候補:

- Glow: 選択、進化、属性チャージ
- Color Matrix: 被弾、行動済み、呪い
- Blur: 高速移動または背景の一時的な焦点調整
- Mask: 水面や魔法陣からの出現
- Displacement: 水・熱・空間の局所的な揺らぎ

制限:

- Filterを常時すべてのタイルへ適用しない。
- Filter適用対象はGame Objectまたは小さなContainer単位とする。
- Camera全体の高負荷Filterは必殺演出など短時間に限定する。
- Filterなしでもイベント内容が理解できる構成にする。
- Phaser 3のPipeline、PostFX、BitmapMask実装例を流用しない。

### 2.6 RenderNodeの方針

Phase 2ではカスタムRenderNodeを作らない。

標準Game Object、Tween、Particle、Blend Mode、Filterで表現できない演出が発生した場合のみ、別設計・別性能検証を行う。水・炎・土・風の通常戦闘演出は標準機能で成立させる。

## 3. 共通エフェクト資産設計

### 3.1 属性ごとの共通セット

各属性は、クリーチャーごとに別素材を作るのではなく、共通エフェクトセットを用意する。

| 属性 | 共通素材 | 動きの特徴 |
|---|---|---|
| 火 | 炎片、火花、火の斬撃、爆ぜる円、煙少量 | 上昇、拡散、瞬間的 |
| 水 | 水滴、泡、波紋、水の斬撃、水しぶき | 曲線、追従、流れ、余韻 |
| 土 | 岩片、砂塵、亀裂、隆起、重い衝撃波 | 低い、短い、重量感 |
| 風 | 風片、細い軌跡、旋風、羽状粒子、空気輪 | 高速、軽い、螺旋 |
| 無 | 白金の光片、幾何学輪、薄い残像 | 静か、対称、短い発光 |

各属性の最低構成:

1. 出現用
2. 移動用
3. 攻撃軌跡
4. 命中
5. 消滅用

### 3.2 素材形式

- 透過PNGまたは透過WebP
- 大きな斬撃・波紋: 単体画像または短いSprite Sheet
- 小粒子: Texture Atlasへ統合
- 1素材内へ余白を過剰に入れない
- 光る素材は白〜淡色を基本にし、Phaser側のTintで属性差を付けられる設計も可
- エフェクトに文字やダメージ数値を含めない
- 方向変更可能な素材は左右反転・回転に耐える形にする

### 3.3 クリーチャー素材

通常クリーチャー:

- 原画: 1024×1024
- 背景なし
- 接地影なし
- 盤面表示用に最適化した派生画像を生成
- 一枚絵＋Phaser変形を基本とする

大型・主要クリーチャー:

- 本体
- 武器または主要攻撃部位
- マント、翼、尻尾など特徴部位

の2〜4パーツ分離を必要に応じて行う。

全クリーチャーの細分化は行わない。通常クリーチャーは一枚絵で成立させ、キングやボスなど演出価値の高い対象だけを分離する。

### 3.4 メタデータ

クリーチャーごとに、画像そのものとは別に演出用メタデータを持つ。

```js
{
  id: 'king',
  anchor: { x: 0.5, y: 0.88 },
  attackOrigin: { x: 0.70, y: 0.46 },
  hitPoint: { x: 0.50, y: 0.42 },
  scaleBoard: 1.0,
  scaleBattle: 1.0,
  motionProfile: 'caster-polearm',
  effectProfile: 'water-royal'
}
```

用途:

- 攻撃エフェクトの発生点
- 命中点
- 接地点
- 盤面・戦闘画面の表示倍率
- 共通モーションの選択

座標は画像内の0〜1正規化座標とし、解像度変更へ耐えるようにする。

## 4. 演出強度と品質レベル

### 4.1 演出強度

同じ共通素材を次の3段階で使用する。

| 強度 | 用途 | Camera | 粒子 | 発光 |
|---|---|---|---|---|
| Small | 移動、軽い回復、小変化 | なし | 少 | 弱 |
| Normal | 通常攻撃、召喚、強化 | 軽い追従・shake | 中 | 中 |
| Special | 侵略決着、進化、必殺 | zoom・短いshake | 多め | 瞬間的に強 |

色や模様を増やして強く見せるのではなく、時間、面積、速度、Camera、停止時間で強弱を作る。

### 4.2 品質レベル

`QualityController`は以下の3段階を持つ。

| 設定 | Filter | 粒子量 | 残像 | Camera shake |
|---|---|---|---|---|
| High | 全許可 | 100% | 許可 | 標準 |
| Standard | 高負荷Filter制限 | 60〜70% | 短縮 | 弱 |
| Lite | 原則なし | 25〜35% | なし | 最小 |

要件:

- オプションから変更可能にする。
- 設定変更に再読み込みを要求しない。
- イベントの意味、尺、結果表示は品質レベルで変えない。
- 自動判定を導入する場合も、ユーザー設定を優先する。
- DOM描画時はLite相当の既存演出を維持する。

### 4.3 演出を減らす設定

画面揺れや強い点滅を減らす設定を用意する。

- Camera shakeを無効または50%以下
- 全画面白フラッシュを局所発光へ置換
- 連続点滅を禁止
- 演出時間は変えず、視覚刺激だけを下げる

## 5. Phase 2A: 演出基盤

### 目的

個別演出を増やす前に、直列制御、キャンセル、Pool、品質設定を成立させる。

### 実装項目

- `EffectDirector`
- `PresentationQueue`
- `EffectPool`
- `CameraDirector`
- `QualityController`
- 演出イベントIDによる重複防止
- Promise完了・タイムアウト・キャンセル
- Phaser/DOM切替時の後始末
- Debug表示

### Debug表示

開発時のみ以下を確認可能にする。

- 現在再生中の演出名
- キュー件数
- 有効Tween数
- Pool使用数
- Particle数
- Camera状態
- 品質レベル

### 完了条件

- ダミー演出を20件連続投入して順序が崩れない。
- 途中でDOM描画へ切り替えても例外が出ない。
- SSE再接続後に古い演出が再生されない。
- 例外を発生させても次のイベントへ進む。

## 6. Phase 2B: 移動ジュース

### 目的

ゲーム時間を伸ばさず、コマ移動を「盤面上を移動している」感覚へ改善する。

### 演出

1歩ごと:

- 出発時に縦方向へ5〜8%縮み、横方向へ3〜5%広がる
- 上昇時に縦方向へ5〜8%伸びる
- 着地時に1回だけ小さく潰れる
- 影は上昇中に小さく薄くなる
- 着地地点へ小粒子を2〜5個

Camera:

- 長距離移動時のみ緩く追従
- 1歩ごとの急なpanを行わない
- 到着マスで既存の停止ズームへ接続

属性差:

- プレイヤーコマの移動では属性エフェクトを常時付けない
- 固有スキルや特殊移動の場合のみ属性軌跡を追加する

### 時間要件

- `GAME_TIMING.stepMs`を変更しない。
- Tweenは既存の1歩時間内に完了させる。
- 移動距離が長くてもサーバー・スマホ側の到着待ちを延長しない。

### 完了条件

- 通常、複数ダイス、城中断・再開が既存タイミングと一致する。
- 4人同一マスで影とコマが破綻しない。
- Lite設定では現行v0.66に近い軽量表示になる。

## 7. Phase 2C: 盤面状態変化

### 7.1 召喚

順序:

1. 対象マスへCamera移動
2. 属性色の小さな紋章または波紋
3. クリーチャーを85%→105%→100%で出現
4. 属性粒子
5. 中央下DOMメッセージ

尺:

- 1.4〜2.0秒

制限:

- 既存のプレイヤー立ち絵カットインは当面DOMで維持する。
- Phaser側は盤面上の出現を担当する。
- 同じ召喚をDOMとPhaserの双方で重複して主役化しない。

### 7.2 強化

- マス外周リング
- レベル段積み更新
- クリーチャーの短い発光
- 小さな上昇粒子
- Cameraは現在そのマスが見えている場合、不要な再移動を行わない

尺:

- 0.8〜1.2秒

### 7.3 進化

順序:

1. 対象マスへzoom
2. 進化前画像を短く発光
3. 属性光または光柱で輪郭を隠す
4. テクスチャを進化後へ切替
5. 光を引かせながら進化後を105%→100%
6. 中央下に進化名

尺:

- 2.0〜2.8秒

Phaser 4:

- GlowまたはColor Matrix Filterは短時間だけ使用する。
- Filterなしでも光柱SpriteとAlpha Tweenで成立させる。

### 7.4 退場

通常退場:

- 彩度低下
- 小さく沈む
- 属性粒子へ分解
- 盤面から削除

水エネルギー体:

- 水滴へ分解し、波紋だけ残して消える

重装クリーチャー:

- 小さな岩・金属片を出し、重量感のある短い沈下

制限:

- アートを粉々に分割する必要はない。
- 本体SpriteのAlpha、Scale、Tintと共通粒子で表現する。

尺:

- 1.2〜1.8秒

### 完了条件

- 召喚、強化、進化、退場が必ず対象マスと結びついて見える。
- state更新より演出が遅れた場合も最終テクスチャが正しい。
- 演出キャンセル後に古いクリーチャー画像が残らない。

## 8. Phase 2D: 経済・連鎖・土地効果

### 8.1 通行料

- 支払者のコマまたは対象マスからコインを発生
- 3〜7枚のコインが曲線で受取側HUDへ移動
- HUD付近で縮小・消滅
- 金額表示はDOM側
- Camera移動を伴わない

品質差:

- High: 7枚＋光跡
- Standard: 5枚
- Lite: 3枚、光跡なし

### 8.2 連鎖成立・増加

- 同属性領地を順番に弱く発光
- 発光は盤面上の実際の連鎖対象だけ
- 最後に中央バナーで倍率を表示
- 全対象を同時に強く点滅させない

順序:

1. 最初の対象マス
2. 近い順または盤面順に波及
3. バナー

### 8.3 連鎖減少

- 対象属性の発光が弱まり消える
- 暗転や赤フラッシュは使用しない
- バナーで新しい倍率を表示

### 8.4 呪い・結界

- 呪い: 紫〜暗色の短い落雷、Color Matrixによる一時的な色変化
- 結界: 透明度の低い輪、衝撃時のみ強く発光
- 常時Filterではなく、通常時は軽量なSpriteまたはGraphics表示

### 完了条件

- 経済変化を演出だけで誤解させず、必ずDOM数値と一致する。
- 連鎖対象でないマスを発光させない。
- 28マスすべてに状態表示があっても性能基準を満たす。

## 9. Phase 2E: 侵略結果の盤面演出

Phase 3の戦闘画面Phaser化より先に、現在のDOM戦闘終了後の盤面変化を強化する。

### 侵略成功

1. 現行DOM戦闘で結果表示
2. 戦闘オーバーレイを閉じる
3. 対象マスへCamera zoom
4. 旧所有色を弱く消す
5. 攻撃属性の短い命中余韻
6. 新所有色・クリーチャーを表示
7. 「土地を奪取」メッセージ

### 防衛成功

1. 現行DOM戦闘で結果表示
2. 対象マスへCamera zoom
3. 防御側クリーチャーを小さく反動させる
4. 防御属性の短い残光
5. 残HPなど必要情報をDOM表示

### 制限

- DOM戦闘内の攻撃演出と盤面の結果演出を同時に再生しない。
- 所有権変更はstate同期後に表示する。
- 結果を演出の成否に依存させない。

## 10. Phase 3: 戦闘シーンのPhaser化

### 10.1 移行判断

Phase 2A〜2EとPhaser 4移行が安定した後に着手する。

以下を満たす場合に実施する。

- 実TVでStandard品質が安定する。
- EffectDirectorと共通属性セットが実運用済み。
- 現行DOM戦闘より明確な改善が見込める。
- クリーチャー素材の表示品質が戦闘サイズで十分。

満たさない場合、現行DOM戦闘を維持する。

### 10.2 推奨構成: ハイブリッド戦闘

戦闘画面全体をCanvasへ移さず、次のように分ける。

| Phaser | DOM |
|---|---|
| クリーチャー本体 | 名前 |
| 踏み込み・反動 | AT / DF |
| 属性攻撃 | HP数値・HPバー |
| 命中・退場 | 支援カード |
| 背景の局所演出 | 戦闘注記 |
| Camera shake | 結果テキスト |

理由:

- 日本語と数値の可読性を維持できる。
- 現行戦闘ロジックとDOM UIを再利用できる。
- Phaserは得意な動きとエフェクトへ集中できる。
- アクセシビリティとレスポンシブ調整が容易。

### 10.3 戦闘Scene

盤面Sceneとは別の`BattleScene`または独立Containerを使用する。

要件:

- 戦闘開始時だけ有効化する。
- 盤面のSSE同期は継続する。
- 戦闘中の盤面演出は保留する。
- 戦闘終了後に確定stateを盤面へ反映する。
- 戦闘Scene失敗時は現行DOM戦闘へ切り替える。
- クリーチャーテクスチャは可能な範囲で共有する。

### 10.4 戦闘シーケンス

#### 開始

1. 背景暗転
2. 攻撃側・防御側を配置
3. 支援カード同時公開
4. AT・DF・HP表示確定

#### 攻撃側

1. 予備動作 180〜300ms
2. 踏み込み 180〜260ms
3. 属性攻撃 250〜450ms
4. 命中停止 50〜90ms
5. 局所発光＋Camera shake 120〜250ms
6. HP更新 500〜900ms

#### 防御成功時の反撃

同じ構造を左右反転して再生する。属性・モーションProfileは防御側クリーチャーのものを使用する。

#### 決着

- 撃破: 退場演出→結果表示
- 生存: 反動から復帰→残HP表示
- 攻撃側帰還: 小さく後退→Fade

### 10.5 一枚絵モーション

通常クリーチャーは一枚絵で次を行う。

- Scale X/Y
- Rotation
- Position Tween
- Alpha
- Tint / Filter
- 短い残像

腕や脚を無理に動かさない。攻撃動作は「予備動作・踏み込み・エフェクト・命中停止」の組合せで成立させる。

### 10.6 モーションProfile

| Profile | 対象 | 主な動き |
|---|---|---|
| melee-heavy | 重装・大型 | 小さい予備動作、重い踏み込み、強いshake |
| melee-fast | 小型・俊敏 | 素早い接近、細い軌跡、短い残像 |
| caster | 魔法型 | 浮上、チャージ、遠隔弾 |
| caster-polearm | キングなど | 武器起点、扇状・直線属性攻撃 |
| beast | 四足・獣 | 全身を低くして突進 |
| floating | 霊体 | 波打つ移動、位置反動、Fade |

Profileは強さやゲーム結果を変えず、見せ方だけを変える。

### 10.7 属性攻撃Profile

水属性の共通例:

```text
water-light:
  小さい水滴 → 細い水刃 → 小さな飛沫

water-normal:
  足元波紋 → 湾曲水刃 → 命中飛沫

water-royal:
  三叉槍チャージ → 大きな一枚の水流 → 王冠状の波紋
```

`water-royal`も共通の水滴、波紋、水刃を再利用し、発生順・Scale・形の組合せで固有感を作る。

火・土・風・無も同じ3階層を持つ。クリーチャーごとに新しい粒子セットを作らない。

### 10.8 Camera・ヒットストップ

- 通常攻撃のshakeは2〜5px相当、120〜220ms
- 大型攻撃は最大8px相当、250ms以内
- 全画面shakeを長く続けない
- ヒットストップは50〜90ms
- ゲームロジックやSSE処理を停止せず、演出Tweenだけを一時停止する
- 演出低減設定ではshakeを無効化し、局所反動だけ残す

### 10.9 戦闘時間

現行戦闘演出の総時間を大幅に超えない。

- 一撃決着: 6〜8秒程度
- 反撃あり: 8〜11秒程度
- 各待機は結果理解に必要な長さに限定
- プレイヤー入力待ちはPhaser演出時間へ含めない

### 10.10 Phase 3完了条件

- 現行DOM戦闘と同じ結果・情報を表示する。
- 攻撃・反撃・撃破・帰還の4分岐を再生できる。
- 全属性で最低1つの共通攻撃がある。
- 一枚絵クリーチャーでも不自然な関節変形がない。
- 80px相当の小表示でも攻撃方向が分かる。
- Standard品質で実TV上30fps未満が継続しない。
- 戦闘Scene失敗時にDOM戦闘へ復旧できる。
