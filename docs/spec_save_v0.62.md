# Summons Crest セーブ/再開 実装仕様(v0.62)

実装済み。設計の経緯とレビュー対応は `plan_save_v0.62.md` を参照。本書は実装された挙動の記録。

## 1. 方式

- サーバーはDB・永続ディスクを使わない。**盤面(board.html)を開いているブラウザのlocalStorageが保存場所**。
- 保険として、セーブデータのJSONファイル書き出し/読み込みに対応(別PCでの再開用)。

## 2. サーバー(server.js)

### 認可: boardToken
- ルーム作成時に`crypto.randomBytes(16)`のトークンを発行(`r.boardToken`)。`/api/create`のレスポンスで盤面にだけ渡す。
- `/api/save`・`/api/close`はトークン必須(不一致は403)。`/api/restore`はセーブJSON内のトークンが権限を兼ねる(ファイル所持者=権限者)。
- `publicState`にはトークンを含めない(参加者に漏らさない)。

### 直列化: serializeRoom(r)
- ルームのフィールドは**分類表**で管理: `ROOM_PERSIST_KEYS`(保存)/`ROOM_RUNTIME_KEYS`(clients・pickTimer・lastActivity=保存しない)。
- 未分類のフィールドが現れると`save_test.js`が失敗する(追加時は必ず分類する)。
- 出力: `{ saveVer: 1, gameVer: VERSION, savedAt, room: {...} }`。

### 検証と復元: validateSave / restoreRoom
- 互換判定は`saveVer`のみ。未来版・非対応版はルーム生成前に拒否。`gameVer`不一致は警告文字列を返すだけ。
- 検証項目: 形状 / コード形式 / トークン長 / フェーズ / プレイヤー数・ID一意・名前長 / カードIDのカタログ存在(全ゾーン+盤面+市場+共通山札) / 数値の有限性・位置範囲 / 領地レベル / pending・battle・draftの参照整合性 / マス番号範囲 / 属性値。
- リクエストサイズ上限2MB(readBody共通)。
- **原子的復元**: 別オブジェクトに複製→検証→成功後に`rooms.set()`。失敗時は既存ルームを一切変更しない。
- **同一コード・同一プレイヤーIDで復元**(スマホの自動復帰を効かせる)。コード衝突は原則409拒否、**既存ルームのトークンとセーブのトークンが一致する場合のみ差し替え**(自ルームの二重復元の救済)。
- 復元時: `clients=new Set()`・`lastActivity=Date.now()`。pendingが`pick_draw`なら候補2枚ごと復元される(v0.63以降は制限時間なし。旧セーブの`until`は破棄)。

### saveRev
- `broadcast()`のたびに単調増加し、`publicState`に含める。盤面の自動セーブ契機。

## 3. 盤面(board.html)

- **オプションメニュー**(v0.63): 左下の「オプション」ボタン →「**セーブして終了**」で、その場で保存→ルームを閉じてタイトルへ戻る(「続きから再開」が表示される)。自動セーブに加えた明示的な保存手段。

- **自動セーブ**: SSE受信時に`state.saveRev`が保存済みrevより進んでいれば`/api/save`→`localStorage['sc_save']`へ上書き(スロット1つ)。in-flight 1本+rev比較で、レスポンス逆順による巻き戻りを防止。保存メタ: rev/savedAt/code/phase/round/プレイヤー名。
- **タイトル画面**: セーブがあれば「続きから再開 ─ 第N周(名前…) M/D HH:MM保存」ボタン(終了済みゲームのセーブでは非表示)。
- **ファイル書き出し**: `summons-crest-save-<CODE>.json`をダウンロード。**ファイルから再開**: メタ付き/生セーブJSONの両形式を受け付ける。
- 復元成功で`sc_board`/`sc_btoken`を更新し、そのままルームに入る。エラーはタイトルの`saveMsg`に表示。
- `/api/close`(ロビー中止・前回ルームを閉じる)はトークン付きで呼ぶ。

## 4. スマホ(phone.html)+ /api/join拡張

- 通常の自動復帰(`sc_session`)は従来どおり。復元ルームは同一コード・同一IDなのでそのまま効く。
- **名前復帰**(v0.62): 進行中ルームにコード+名前で参加すると、同名の**切断中**プレイヤーを引き継ぐ(接続中は拒否=乗っ取り不可)。名前は前後空白除去のうえ完全一致。
- ロビー参加時の**同名重複を禁止**(名前復帰の一意性を保証)。
- 参加画面に案内文「進行中のゲームには、参加時と同じ名前で入り直すと復帰できます」。

## 5. テスト(save_test.js ─ npm testに常設)

- **A-1**: 40手ごとにセーブ→復元を挟みながらランダムゲームを完走(全pending状態の往復を網羅)。分類表・往復一致・カード保存則を毎手検証
- **A-2**: pick_draw中の復元→制限時間の張り直し・タイムアウトが一度だけ効く
- **A-3**: 不正セーブ12種(未来版/旧版/未知カード/重複ID/範囲外/肥大ゾーン等)の拒否+既存ルーム無変更
- **A-4**: コード衝突(トークン不一致=409拒否/一致=差し替え)
- **A-5**: publicStateにboardTokenが漏れない
- **B(実サーバー)**: create→join(同名拒否)→保存の認可(無/誤/正トークン)→進行中参加拒否→名前復帰でID一致→クローズの認可→復元→resume疎通

## 6. 既知の割り切り

- v1.08以降は市場滞在中の`shopVisit`(来店ID・商品8枠・価格・売り切れ・半額状態)も保存する。旧セーブの宝石・秘宝フィールドは復元時に破棄する。
- v1.09以降はULTカットイン中の`ultSequence`(発動者・効果・開始/解決時刻・解決データ)を保存する。`ultTimer`は保存せず、復元時に残り時間から再設定し、期限経過済みなら効果解決へ進む。

- セーブJSONには全員の手札・山札が平文で入る(盤面PCの中身を覗けば見える)。身内プレイ前提で許容。
- 自動セーブは状態変化(broadcast)契機のため、最悪でも直前の操作までしか巻き戻らない。
- `/api/action`自体は従来どおり無認証(全体認証はスコープ外・将来課題)。
